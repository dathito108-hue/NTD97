# NTD97 Sovereign Model Contract

Status: canonical Phase 002 contract.

## Identity

NTD97 is one independent mobile AGI model.

It is not a shell that selects external LLMs. It is not defined by GGUF, ONNX, SafeTensors, TFLite, a cloud API, or a particular vendor inference engine.

The stable identity is the NTD97 native state:

```text
SIK97 + NTD97 IR + NCC97 native intelligence + sovereign memory + capabilities
```

## Intelligence assimilation rule

Any supported intelligence source is treated as material to be assimilated.

Sources may include:

- model weights;
- execution graphs;
- tokenizers/codecs;
- adapters;
- structured knowledge;
- documents/knowledge corpora;
- procedural skills;
- capability definitions;
- learned deltas produced locally.

A source becomes part of NTD97 only through:

```text
inspect
-> parse
-> normalize
-> convert
-> validate
-> atomic native commit
-> activate
```

Once committed:

- the intelligence has an NTD97-native identity/address;
- it is stored as NCC97-native chunks/state;
- it participates in NTD97 routing, memory and reasoning;
- provenance remains available;
- the original source runtime is not required for normal execution.

## Native ownership

"Becomes NTD97 intelligence" does not mean deleting provenance or falsely claiming authorship of imported material.

It means the **execution representation, storage lifecycle, routing and integration are native to NTD97**.

Licenses and provenance must remain attached to imported material where applicable.

## No mandatory third-party intelligence dependency

The sovereign baseline must be able to:

1. boot without internet;
2. load NTD97 native intelligence;
3. restore memory and active checkpoints;
4. understand local user input;
5. reason locally;
6. plan locally;
7. use installed local capabilities;
8. execute and verify local tasks;
9. export a backup.

Internet, external APIs and paired computers may improve reach or performance, but cannot be required for the identity to exist.

## NTD97 IR

NTD97 IR is the internal representation between imported intelligence and the mobile execution substrate.

Planned IR families include:

- tensor ops;
- attention/state ops;
- routing ops;
- memory ops;
- multimodal codec ops;
- control-flow ops;
- capability/tool ops;
- verification ops.

The IR is versioned independently from import formats.

## Cognitive compression

The runtime should avoid loading all intelligence into active RAM when the task does not need it.

The long-term architecture permits:

- task-conditioned expert activation;
- content-addressed tensor paging;
- state/prefix reuse;
- adapter activation;
- knowledge retrieval;
- device-specific quantization;
- hot/cold intelligence tiers.

The goal is to make the **active working intelligence** fit the phone while preserving a larger native intelligence store.

## Evolution

NTD97 may improve capabilities, adapters and components, but activation follows a transaction:

```text
candidate
-> isolated build/transform
-> tests
-> benchmark
-> compatibility verification
-> signed/versioned commit
-> atomic activation
```

The previous known-good state remains rollback-capable.
